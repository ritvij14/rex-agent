# Pi profile adapter instructions

This private adapter connects `@rex/profiles` to Pi 1.3.0. Inherit root and `packages/` rules. `src/index.ts` owns the SDK run boundary; `src/proposals.ts` owns draft/admission filesystem operations; `src/cli.ts` is the sandbox command. No Pi/provider imports belong in the core package.

## API and authority

Public exports are `runProfileRequest`, `IncompleteProfileResponseError`, `createProposal`, `reviewProposal`, and `approveProposal`, plus their types/constants. Import other Rex packages through public exports. Dependencies are pinned Pi Coding Agent 1.3.0, TypeBox 1.3.27, and the core workspace. The optional MCP SDK 1.32.1 is development-only, to satisfy Google's published declaration imports; it does not enable MCP. Root tools execute/typecheck this source-only package; no emitted build exists.

Every request starts with an explicit `profile: <id>` line. Keep the entire SDK prompt/tool loop inside `ProfileRuntime.run`. Construct profile-specific session storage, explicit model/runtime, in-memory settings and an isolated resource loader. Never import host auth/settings or discover project extensions, MCP servers, skills, prompts or instructions. A selected profile never inherits another profile's history or tool authority. Effective configuration comes from `resolveEffectiveProfile`: when `<profiles-root>/shared` exists, version-2 SOUL profiles resolve the operator's shared model/tool defaults and mandatory blacklists; without that directory the adapter retains version-1 inline-only operation and fails closed for SOUL profiles before inference. `requireRunnable` accepts the resolved effective configuration, not the raw definition.

Whitelist/blacklist covers registered tool names only: `*` or exact names, blacklist wins, default deny. Enforce it in the execution hook, including indirect calls, not merely model-visible tools. Unregistered or unsupported tool rules fail before inference. The initial host-approved tool catalog is `read`, `bash`, `edit`, `write`, `ls`, and `propose_profile`. Pi's download-dependent `grep`/`find` tools are excluded. No Codemode/MCP/user-shell shortcut interface is exposed by this command. An allowed `bash` can still access the container filesystem; tool rules are not path confinement.

`propose_profile` can write a new validated draft, never active definitions. Approval is a separate operator operation with an exact canonical SHA-256 digest and no overwrite. In the sandbox, definitions are a read-only volume for the agent; the networkless operator helper mounts it writable, has no inference socket/auth, and alone performs approval. Never approve a draft merely because the model requested it. Tests may call admission against synthetic writable roots; normal agent tools must not.

The OpenAI-compatible adapter sends no client output-token cap. Pi 1.3.0 requires numeric metadata; `maxTokens: 0` omits the wire limit, and tests assert both output-limit fields are absent. Abort on a finalized length-stopped response, reject with the fixed public `IncompleteProfileResponseError`, suppress partial CLI stdout and release the lock. Do not automatically retry truncated tool calls or pretend earlier completed actions were rolled back.

The `.dockerignore` explicitly permits only manifest/runtime sources for its named build context. Keep tests, development declarations, private state and arbitrary new files out of the image/context. The CLI entrypoint is exported as `./cli`; the operator entrypoint as `./operator`.

## Verification

From the root, `npm test` runs `packages/*/tests/*.test.ts`, `npm run typecheck` covers this package, and `npm run check` includes privacy and formatting. `tsconfig.json` uses strict Bundler/DOM checking for Pi's JSON-import/web-provider declarations; root NodeNext checking remains unchanged for core/repository code. Do not add `skipLibCheck`, fake declarations or patches to installed dependencies. Node execution compatibility is covered by real SDK/container tests. Adapter tests use a local synthetic inference endpoint and real Pi sessions/tools, never accounts. Cover selector rejection before inference, model/role/tool setup, wildcard-deny precedence, forged denied calls without side effects, per-profile history, concurrency locks/failure cleanup, draft validation and digest-bound admission. Container acceptance verifies installation and read-only active definitions, plus real CLI truncation failure and recovery. The installed `src/verify.ts responses` mode uses synthetic loopback inference and owned temporary state only, so it can verify a refreshed normal container without touching its histories or paid proxy. Keep text/empty/tool truncation, prior tool effects, lock cleanup and cap-free wire requests covered. Necessary live inference QA follows the root standing approval and low-cost model policy; no per-run confirmation is needed. Test the target model when compatibility requires it, and never print raw API bodies or account data.

`createProposal` requires a trusted provenance argument `{ operation, origin }` supplied by Rex callers (the builder tool records its own runtime profile; the model never supplies it). Drafts store `provenance.json` with the operation, origin, active base digest (updates only) and shared-configuration digest at draft time. The admission digest (`bundleDigest`) covers the canonical whole bundle — manifest fields plus `SOUL.md` text for persona bundles. `reviewProposal` returns the bundle, digest and provenance; `approveProposal` enforces create-destination vacancy, update same-origin/base-digest/shared-digest checks, stages the new bundle beside the destination and swaps it in by directory rename, then removes the consumed draft. `sharedConfigurationDigest` exposes the shared configuration digest for trusted callers. Update-draft tool wiring for self-maintenance is a later unit; admission is complete.
