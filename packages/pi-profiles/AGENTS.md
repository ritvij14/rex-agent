# Pi profile adapter instructions

This private adapter connects `@rex/profiles` to Pi 1.3.0. Inherit root and `packages/` rules. `src/index.ts` owns the SDK run boundary; `src/proposals.ts` owns draft/admission filesystem operations; `src/cli.ts` is the sandbox command. No Pi/provider imports belong in the core package.

## API and authority

Public exports are `runProfileRequest`, `IncompleteProfileResponseError`, `createProposal`, `reviewProposal`, and `approveProposal`, plus their types/constants. Import other Rex packages through public exports. Dependencies are pinned Pi Coding Agent 1.3.0, Pi MCP 1.3.0, TypeBox 1.3.27, and the core workspace. The optional MCP SDK 1.32.1 is development-only, to satisfy Google's published declaration imports; it does not enable MCP. Root tools execute/typecheck this source-only package; no emitted build exists.

Every request starts with an explicit `profile: <id>` line. Keep the entire SDK prompt/tool loop inside `ProfileRuntime.run`. Construct profile-specific session storage, explicit model/runtime, in-memory settings and an isolated resource loader. Never import host auth/settings or discover project extensions, MCP servers, skills, prompts or instructions. A selected profile never inherits another profile's history or tool authority. Effective configuration comes from `resolveEffectiveProfile`: when `<profiles-root>/shared` exists, both legacy and SOUL profiles receive the shared persona and mandatory denials; SOUL profiles additionally resolve missing model/tool defaults; without that directory the adapter retains version-1 inline-only operation and fails closed for SOUL profiles before inference. `requireRunnable` accepts the resolved effective configuration, not the raw definition.

Whitelist/blacklist covers registered tool names only: `*` or exact names, blacklist wins, default deny. Enforce it in the execution hook, including indirect calls, not merely model-visible tools. Unregistered or unsupported tool rules fail before inference. The built-in host-approved tool catalog is `read`, `bash`, `edit`, `write`, `ls`, `propose_profile`, opt-in `codemode`, and `tool_search` (registered only for selected indirect MCP exposure); explicitly selected installed extensions may add catalog-declared names under the same execution policy. Pi's download-dependent `grep`/`find` tools are excluded. Explicitly selected local MCP tools/resources can also be called by Codemode when resources.codemode is selected and the tool policy allows codemode. Register the public factory with models:false and preserve the same nested policy. Catalog exposure codemode/deferred leaves MCP tools out of the initial declarations; native tool_search loads only registered, allowed tools and needs its own grant. Built-in tools are name/factory entries checked against actual registration. Return actual active declarations as toolNames. Selected remote MCP servers connect through a trusted-caller-supplied loopback connector-router origin (validated strictly); the relay holds credentials. No host/server configuration discovery or user-shell shortcut interface is enabled. An allowed `bash` can still access the container filesystem; tool rules are not path confinement.

`propose_profile` can write a new validated draft, never active definitions. Approval is a separate operator operation with an exact canonical SHA-256 digest and no overwrite. A worker receives only its selected read-only definition snapshot and private state/drafts. The CLI refuses a definitions root containing multiple profiles; the SDK alone is not filesystem isolation. Only the operator helper sees the writable master. The helper has no inference socket/auth. Create approval reads the fixed builder volume and rejects non-builder or update provenance. Update approval reads only the target profile's volume. It snapshots read-only proposals into temporary private storage before approval; original source drafts remain, with destination vacancy preventing replay. Never approve a draft merely because the model requested it. Tests may call admission against synthetic writable roots; normal agent tools must not.

The OpenAI-compatible adapter sends no client output-token cap. Pi 1.3.0 requires numeric metadata; `maxTokens: 0` omits the wire limit, and tests assert both output-limit fields are absent. Abort on a finalized length-stopped response, reject with the fixed public `IncompleteProfileResponseError`, suppress partial CLI stdout and release the lock. Do not automatically retry truncated tool calls or pretend earlier completed actions were rolled back.

The `.dockerignore` explicitly permits only manifest/runtime sources for its named build context. Keep tests, development declarations, private state and arbitrary new files out of the image/context. The CLI entrypoint is exported as `./cli`; the operator entrypoint as `./operator`.

## Verification

From the root, `npm test` runs `packages/*/tests/*.test.ts`, `npm run typecheck` covers this package, and `npm run check` includes privacy and formatting. `tsconfig.json` uses strict Bundler/DOM checking for Pi's JSON-import/web-provider declarations; root NodeNext checking remains unchanged for core/repository code. Do not add `skipLibCheck`, fake declarations or patches to installed dependencies. Node execution compatibility is covered by real SDK/container tests. Adapter tests use a local synthetic inference endpoint and real Pi sessions/tools, never accounts. Cover selector rejection before inference, model/role/tool setup, wildcard-deny precedence, forged denied calls without side effects, per-profile history, concurrency locks/failure cleanup, draft validation and digest-bound admission. Container acceptance verifies installation and read-only active definitions, plus real CLI truncation failure and recovery. The installed `src/verify.ts responses` mode uses synthetic loopback inference and owned temporary state only, so it can verify a refreshed normal container without touching its histories or paid proxy. Keep text/empty/tool truncation, prior tool effects, lock cleanup and cap-free wire requests covered. Necessary live inference QA follows the root standing approval and low-cost model policy; no per-run confirmation is needed. Test the target model when compatibility requires it, and never print raw API bodies or account data.

`createProposal` requires a trusted provenance argument `{ operation, origin }` supplied by Rex callers (the builder tool records its own runtime profile; the model never supplies it). Drafts store `provenance.json` with the operation, origin, active base digest (updates only) and shared-configuration digest at draft time. The admission digest (`bundleDigest`) covers the canonical whole bundle — manifest fields plus `SOUL.md` text for persona bundles. `reviewProposal` returns the bundle, digest and provenance; `approveProposal` enforces create-destination vacancy, update same-origin/base-digest/shared-digest checks, stages the new bundle beside the destination and swaps it in by directory rename, then removes the consumed draft. `sharedConfigurationDigest` exposes the shared configuration digest for trusted callers. The library's writable-root approval consumes its draft; the installed helper consumes a temporary snapshot, not the original read-only source. Create commands accept only builder creation. `revise_profile` is exposed only when the host passes `--maintain`, and it can draft an update only for the running profile without adding tools. `approve-update` reads that profile's volume, not a model-selected source. Do not interpret model-writable provenance metadata as trusted identity: the operator chooses the originating source volume independently.

SOUL revisions retain the version-2 format and omitted overrides; never copy the concatenated shared instructions into the profile persona. `createProposal` accepts optional SOUL text as its fifth argument only for a version-2 definition, bounded to 16384 bytes and non-whitespace. Digests include that text. Exercise the SOUL draft, approval, and fresh-turn journey alongside legacy maintenance.

When shared `models` is present, reject an unlisted model before inference and use the selected catalog entry for Pi API/context/output/reasoning metadata. Keep all endpoints on the fixed relay. Anthropic registration uses the relay origin because its client appends `/v1/messages`; OpenAI registration uses the `/v1` base. Thinking defaults to off. A non-off model-reference thinking level requires catalog reasoning capability on every candidate and is passed to Pi and reapplied on fallback.

`modelOverride` selects one allowed catalog model for a request. Use the selected ID for provider registration, session model, and returned diagnostics, but keep draft inheritance tied to the profile definition rather than persisting a one-turn override. Host and installed commands share `parseProfileArguments` from the core.

`planProfileModels` supplies bounded catalog-approved candidates. An explicit override disables fallback. The adapter observes structured HTTP status through a per-runtime injected fetch, not error-body parsing. Fallback is permitted only for 429/502/503/504 before streamed content or tool calls. Before retry, branch the session manager to the original leaf, refresh context, and persist the new model selection. Keep lock, deadline, request budget, and policy shared across attempts. Never retry after truncation or tool activity.

Use resolved turn limits for the total deadline timer, provider timeout, shared request counter, and pre-prompt history admission. Clear the timer and release the lock on every normal/error/abort path. CLI must not impose a second fixed 90-second timeout over a configured longer turn. Preserve limits in revision bundles and operator snapshots, without exposing a model tool to edit them.

Instruction resources are frozen by the core lookup. Preserve resource references and resourceFiles through SOUL maintenance, whole-bundle hashes, staged activation and operator snapshots. createProposal accepts instruction-file records as its sixth argument and validates exact reference matches before writes. The public ./proposals subpath exposes writeResourceFiles to trusted provisioning; use it only with a newly created/cleared destination controlled by the operator, never an arbitrary model path. It rejects unsafe references and writes only selected Markdown text.

Only selected skills load via loadSkills(includeDefaults:false), supplied through skillsOverride while noSkills stays true. Prompts use explicit additionalPromptTemplatePaths while noPromptTemplates stays true. Reject all resource diagnostics/collisions before inference. Enable template expansion only when selected templates exist. Skills require an allowed read tool; they never grant tools or enable filesystem discovery. Selected Markdown files participate in every bundle/snapshot path; executable helper files are not supported by this text-resource slice.

Workspace instructions require explicit shared/own resources.workspaceInstructions references. Read the union once from the selected cwd under the turn lock, append frozen text to the prompt, and never walk ancestors or discover conventional names. Workspace content is dynamic and is not copied into profile snapshots or approved as definition bytes. Do not grant tools because a selected project file requests them.

Installed extension references are data IDs, never paths/downloads. The trusted caller supplies installedExtensionsRoot; CLI uses the fixed immutable image directory. Preflight all selected regular bounded module hashes before import, reject reserved names and actual registration mismatches, and admit custom tool grants only against the operator catalog. Installed code is fully trusted, not sandboxed by tool-name checks. Disable fallback with installed extensions to avoid replaying lifecycle side effects. Tests cover mismatched hashes, missing roots, symlinks, all-before-any import preflight, selected-only import, blacklist/nested denial, registration mismatch and custom-tool admission narrowing.

src/local-mcp.ts owns selected local MCP clients. Use the public pi-mcp protocol client and fixed node executable, no default MCP extension/auth/config discovery. Verify every selected regular bounded MJS artifact before starting any selected server; src/installed-modules.ts shares this reader with extensions. CLI fixes /opt/rex/operator-mcp; SDK root is trusted caller input. Start only under a managed requested turn, await initialization and exact declared tools before inference, use inheritEnv:false with fixed PATH/LANG and owned temporary HOME/TMPDIR and own cwd. Close transport/client and remove owned temp storage on success, failure or cancellation before releasing the profile lock. No reconnect/replay/fallback; tool-list changes, dropped connections, protocol-call failures and invalid/oversized results invalidate the turn before another model request; the tool_call hook also refuses every later tool dispatch once the connection is unusable, so a script that catches an MCP error cannot cause further effects. Resource opt-in additionally requires server capability; register list_mcp_resources/list_mcp_resource_templates/read_mcp_resource once. Require an exact explicitly selected resource-enabled server ID on every call; lists return one page and cursor forwarding is explicit. Resource calls use the same perform result bounds, cancellation, invalidation and cleanup as ordinary MCP tools. Only a templates method-not-found code maps to an empty page. Omit private _meta, icons and other non-public descriptors; never discover resource bodies automatically. MCP tool rules and actual selected availability both apply; an update cannot add a connected server even through wildcard grants. Test process effects, PID exit, minimal environment (macOS adds __CF_USER_TEXT_ENCODING even to empty environments), literal args, denied calls, hash/missing-root/metadata refusal, deadline cleanup and recovery. Live isolation checks must use actual selected-only worker snapshots, not standalone image containers that still contain public templates. openMcpSession also opens selected remote servers through the shared registration path with StreamableHttpTransport to a strictly validated local-loopback remoteMcpOrigin, openGetStream:false, no reconnection and redirect errors; remote-only turns register the abort listener too, and cancellation closes remote sessions with DELETE.

resources.references contains explicit supporting Markdown copied/digest-bound with other resourceFiles but not passed as skills/templates/system instructions. Tests must distinguish absence from the initial prompt and actual successful read of selected support; keep their content and references through draft activation/provisioning. Code helpers still require operator installation.
